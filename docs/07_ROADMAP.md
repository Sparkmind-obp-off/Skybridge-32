# Skybridge 32 — Roadmap

## Phase 0 — Foundation

Status: ready

- product definition;
- race profile;
- training philosophy;
- architecture;
- UX;
- data model;
- implementation prompt.

## Phase 1 — V0 Local-First PWA

Build now:

- PWA shell;
- Today dashboard;
- countdown;
- workout schedule;
- Run/Walk Coach;
- local logs;
- progress;
- Race Prep checklist;
- Mager Mode;
- offline shell;
- export/delete.

Exit criteria:

- app usable on phone;
- timer works offline;
- logs persist;
- first real workout can be recorded.

## Phase 2 — Real-Use Adaptation

After several real sessions:

- RPE-based adjustment;
- recent-session summary;
- missed-session handling;
- recovery prompts;
- better Mager Mode;
- audio/vibration polish.

Exit criteria:

- app recommendations match actual training experience.

## Phase 3 — Race Rehearsal

- 5K simulation gate;
- race strategy card;
- race-day mode;
- final checklist;
- taper logic.

Exit criteria:

- user has a rehearsed strategy and understands race-day workflow.

## Phase 4 — Optional Utilities

Only if useful:

- weather;
- GPS;
- richer export;
- calendar integration.

## Phase 5 — Optional Sync

Only if the local-first model becomes limiting:

- Cloudflare Worker;
- D1;
- encrypted/authenticated sync;
- device recovery.

## Phase 6 — Optional Integrations

Potentially:

- Strava;
- wearable imports;
- AI coach.

These are not prerequisites for race readiness.

## Anti-roadmap rule

Do not spend the 32-day preparation window building infrastructure that does not improve today's training.

The user's actual training log is the primary product feedback.
