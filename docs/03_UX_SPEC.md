# Skybridge 32 — UX Specification

## Tone

Calm, practical, friendly, slightly playful.

Never:

- shame;
- compare;
- pressure;
- imply failure because of walking;
- encourage reckless effort.

## Navigation

Primary tabs:

1. Today
2. Coach
3. Progress
4. Race Prep
5. Race Day

## Today screen

Header:

**SKYBRIDGE 32**  
**BIB #6 — HAIDAR**  
**5K**  
**8 NOV 2026**

Main card:

**TODAY**

Example:

**Run-Walk — 30 min**  
3 min RUN / 2 min WALK × 6

Primary CTA:

**START**

Secondary action:

**MAGER MODE — 10 MIN**

## Coach screen

Large:

**RUN**

Below:

**02:41**

Then:

**Next: WALK — 02:00**

Controls:

- Pause
- Resume
- End

Optional:

- vibration;
- spoken phase cue;
- audio cue.

## Completion screen

Show:

- completed duration;
- optional distance;
- RPE;
- soreness;
- notes.

Copy should celebrate completion without implying athletic achievement.

Example:

> Selesai. Bagus. Sekarang recovery.

## Progress screen

Use simple cards:

- Sessions
- Active time
- Longest session
- Recent RPE
- Current phase

Avoid vanity metrics that create pressure.

## Race Prep

Checklist items can be checked and persisted locally.

Show organizer-dependent information separately from personal preparation so that assumptions are not mistaken for official rules.

## Mager Mode

Copy:

> Lagi mager? Nggak perlu mikir jauh. Jalan/gerak santai 10 menit dulu.

After 10 minutes:

> Kalau mau lanjut, lanjut. Kalau cukup, selesai juga nggak apa-apa.

## Accessibility

- minimum comfortable touch target around 44px;
- semantic controls;
- keyboard navigation;
- visible focus;
- reduced-motion support;
- labels for timer states;
- no information conveyed by color alone.

## Offline UX

Show a small status indicator:

- Ready offline
- Sync not required

No blocking network dependency for core training.
