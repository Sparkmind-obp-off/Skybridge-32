# Skybridge 32 — Training Engine

## 1. Training philosophy

The runner starts from a beginner baseline. The engine prioritizes gradual exposure to longer easy activity over speed.

Primary variable:

**time on feet**

Secondary variables:

- run/walk ratio;
- session frequency;
- RPE;
- soreness;
- optional distance.

## 2. Inputs

The engine may use:

- days remaining;
- recent session count;
- recent active minutes;
- longest recent session;
- optional distance;
- RPE;
- soreness/pain flag;
- missed-session history;
- current phase.

## 3. 32-day structure

### Days 1–7 — Baseline

Purpose:

- establish consistency;
- discover comfortable effort;
- find an initial run/walk rhythm.

Target: approximately 3 easy movement sessions.

Example sessions:

- 20–25 min easy;
- 25–30 min easy;
- 30–35 min baseline.

No pace target.

### Days 8–16 — Foundation

Target: approximately 3 sessions/week.

Example run/walk patterns:

- 2 min easy run / 2 min walk;
- 3 min easy run / 2 min walk;
- 4 min easy run / 2 min walk.

Only progress when the current pattern feels controlled.

### Days 17–24 — Build

Three broad session types:

1. longer easy session;
2. controlled interval/run-walk session;
3. easy recovery session.

The longest session increases gradually.

### Days 25–28 — Race-specific

Goals:

- rehearse the intended run/walk strategy;
- practice starting conservatively;
- test hydration/fueling habits that are already tolerated;
- perform a 5K simulation only if readiness supports it.

A simulation is optional, not a test of worth.

### Days 29–31 — Taper

Reduce volume.

Priorities:

- recovery;
- sleep;
- familiar routine;
- confidence;
- equipment readiness.

Do not introduce hard new workouts.

### Day 32 — Race day

Use the rehearsed strategy.

Start easier than excitement suggests.

## 4. Adaptation rules

### Green

If:

- RPE is controlled;
- no concerning pain;
- recovery feels normal;

then maintain or make a small progression.

### Yellow

If:

- RPE is unusually high;
- soreness persists;
- sleep/recovery is poor;
- a session feels significantly harder than expected;

then repeat the same load or reduce it.

### Red

If:

- concerning pain;
- chest pain;
- fainting/dizziness;
- severe unusual shortness of breath;
- acute illness;

then stop exercise and seek appropriate medical attention.

The engine must not prescribe training progression in red status.

## 5. Load progression rules

- Never compensate for a missed workout by doubling the next workout.
- Avoid increasing duration and intensity substantially at the same time.
- Prefer small duration changes.
- Recovery days are part of the plan.
- A shorter successful session is better than an abandoned ambitious session.

## 6. Readiness heuristic

The app may classify readiness as:

- Building;
- On track;
- Needs recovery;
- Race-ready rehearsal complete.

This is a product status, not a medical or physiological diagnosis.

## 7. 5K simulation gate

A 5K rehearsal should be offered only when the recent history indicates adequate tolerance for a longer continuous activity and no red flags.

The app should never force a 5K simulation simply because the calendar says so.

## 8. COT interpretation

Official COT = 90 minutes.

Equivalent average pace is 18:00 min/km.

The app should display COT as a boundary, never as a recommended training pace.

A user who can comfortably rehearse the distance with meaningful buffer has a stronger preparation signal than someone merely training to survive exactly 90 minutes.
